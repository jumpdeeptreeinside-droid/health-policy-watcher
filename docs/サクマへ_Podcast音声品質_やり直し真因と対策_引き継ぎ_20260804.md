# サクマへ：Podcast音声品質「やり直し8割」の真因と対策 引き継ぎ 2026-08-04

翔太さんの相談「にんげんの耳を通すと大体だめ（体感8割）」を調査し、真因3つを特定して修正、
やり直し21本を再生成、承認済み3本を本番配信するところまで完了した。明日の作業のための引き継ぎ。

**一行で**: 原因は辞書の膨張ではなく、**①全角記号の正規化漏れ ②1〜2桁の数字＋助数詞の未処理 ③ユーザー辞書の1文字エントリ**。
①②は`yomi_preprocess`、③は`dic.json`の掃除で解消。加えて**AI検品の自動辞書登録を止めて承認制にした**。

---

## 1. 最初に立てた仮説は外れている（同じ穴を掘り直さないこと）

「AI検品が辞書を汚す→抑揚が壊れる」という仮説を立てたが、**実測で棄却した**。

- 試聴フォルダの3サブフォルダをそのまま合否ラベルとして使える（合格23 / 不合格20 / 再不合格5）
- 掃除対象エントリの発火数は **合格0.6 vs 不合格0.7 で差なし**
- 同一台本でA(現行辞書)/B(掃除後)を合成 → **mp3がmd5一致**（＝辞書は音に何も影響していなかった）

**教訓**: 「もっともらしい原因」を音で検証せずに手を入れない。合否ラベル48本が手元にあるので、仮説は必ずそれで検定する。
検証コードは `src/diagnose_rejections.py`、台本キャッシュは `output/dict_cleanup/scripts_cache.json`（48本＋ラベル）。

## 2. 本当の理由はNotion台本のハイライトに記録されていた

`rework_flagged_episodes.read_highlights()` で読める。**やり直し25本中21本に人の指摘が残っていた**。
中身はほぼ全部が数字・助数詞（`1人` `1日` `2日` `．4日` `．7日` `対` `名` `組` `分` `4` `5` `0` `7`）。

**緑さんの読み間違いメモ(gsheet)は今も0語**。ログに「0語を反映」が590回。
＝**誤読理由の実質的な正本はNotionのハイライト**。次に原因を知りたくなったら、まずここを読むこと。

## 3. 特定したバグ3つ

### ① 全角「，．」が半角化されていなかった（`yomi_preprocess.to_yomi`）
```
１，８０３人  →  1，はっぴゃくさんにん      数値が真っ二つ
77．1%      →  77．いちパーセント        ハイライトの「．4日」「．7日」の正体
```
translate表に `０-９` と `％` はあったが `，．` が無かった。

### ② 1〜2桁の数字＋助数詞が丸ごと未処理
旧コードのコメント「1〜2桁は素直に読めるので温存」が**前提から誤り**。読みが変わるのは全部ここだった。
```
1月 / 2つ目 / 第1回 / 4日間 / 1日 / 5か月 / 1人 / 15歳 / 5割  → 全部そのままVOICEPEAKへ
```
→ `apply_counters()` を新設（つ目/つ/か月/箇所/日間/年間/年連続/年度/年/月分/月/日/品目/施設/歳/回/割/倍/次/位/号/期/種/床/対/名/件/組/人/本）。
促音便・小数・万億兆つきに対応。`本` だけ末尾桁で ほん/ぼん/ぽん が変わるので関数化（`_hon_yomi`）。

### ③ VOICEPEAKユーザー辞書の1文字エントリ（← これが「にちほんにん」の犯人）
```
'日' → ニチ   priority 8
'人' → ヒト   priority 8（priority 7 にも重複登録）
'科' → カ / '六' '四' '十' '+'
```
`日本人→ニホンジン`(priority 9) が**正しく登録済みなのに1文字エントリに負けて分断**されていた。
同一文を辞書だけ変えて合成 → md5が変わり 8.25秒→8.12秒（`src/dict_1char_test.py`）。
→ `clean_voicepeak_dict.py --write-1char-only` で8語だけ削除。**426→418語**。

### おまけ: 略語置換に単語境界が無かった
```
AIDS → エーアイDS / UNAIDS → UNエーアイDS / WHOLE → ダブリューエイチオーLE
```
`sub_acronyms()` を新設し、**英字に挟まれたときだけスキップ**（数字が続くのは `WHA79` `COVID19` なので置換してよい）。
`AIDS→エイズ` `UNAIDS→ユーエヌエイズ` も辞書に追加。

## 4. 運用の穴（コード以外）

### レビューメモが読み上げられていた
台本に人が書いた `（以下、音声内にこのスクリプトに記載のない文章がある）` を `md_to_plain` が素通りさせていた。
療養病床の回が2回やり直しになった一因。→ `REVIEW_NOTE` 正規表現で除去するようにした（本番反映済み）。

### 台本自体の誤字
`出来さ`（出来事）、`議論が行わました`（行われました）。**Gemini生成側の問題で音声の問題ではない**。
今日は該当2件をNotionのブロック単位でPATCHして修正した。翔太さんの許可を都度取ること（本文改変のため）。

### AI検品がほぼ機能していなかった
合格 **5/78（6%）**。ほぼ常に何かを指摘し、その指摘を無条件で `dic.json` に `priority=9 / accentType=0` で登録していた。
`人→ヒト` `日→ニチ` はこれが作ったもの。→ **自動登録を廃止**し `output/dict_pending.json` の承認待ちキューへ。
足切り(`dict_entry_ok`)＝1文字/12字超/数字を含む/助詞・活用形で終わる/読みがカタカナでない、を却下理由つきで記録。
**再合成もやめた**（辞書が変わらないので意味がない＋合成時間が半分になる）。

## 9. 罠メモ（次に踏まないように）

- **Notionの「公開待ち」は試聴共有ではなく本番配信**。次の毎時:15で `publish_episode` が git push まで走り、
  Apple/Spotify/Amazonへ即出る。**しかも成功後にローカル正本とDrive試聴コピーを自動削除する**。
  誰かに聴かせたいだけならDriveフォルダを直接共有すること。
- **公開が読むmp3は `AudioPath` が指す OUT_DIR のローカル正本**。別フォルダに作った修正版は公開経路に乗らない。
  承認済みmp3をそのまま配信したいときは `src/stage_approved_mp3.py`（再合成せずコピー＋md5照合）。
- **`rework_flagged_episodes.py` はflockを取っていなかった**（`process_notion` を直接呼ぶため）。
  毎時:15のlaunchdと重なると二重処理になる。→ 同じ鍵を取るよう修正済み。
  なお自分の実行がロックを持つ間、launchd側はスキップされる（公開も自分の実行の最後に走る）。
- **やり直しフォルダに公開待ち/公開済みのmp3を残さない**。`rework` が `音声化待ち` に戻して作り直し、公開が取り消される。
- **macOSのファイル名はNFD**。`'死亡数が大幅減少' in filename` が濁点のせいで外れる。
  必ず `unicodedata.normalize('NFC', f)` を通すこと。今日2回踏んだ。
- **Whisperは誤読検出に使えない**。ASRは聞こえた音を正書法に戻すので、`床=ゆか/しょう` も `日本人=にちほんにん` も
  同じ「日本人」と書き起こされる。検出できるのは数字と脱落だけ。**読みの判定は人の耳しかない**（今のところ）。
- **VOICEPEAKユーザー辞書に1文字を入れない**。複合語が分断される。
- VOICEPEAK CLIは対話シェルから呼ぶと `iconv_open is not supported` で1回目が失敗しがち（3回リトライで通る）。
  ログに出ていても異常ではない。ただし**チャンク欠落の可能性があるので長さで検証すること**。
