翔太さんの依頼「1回目・2回目のやり直しフォルダの音源を作り直して」を受けて調査し、
真因を特定して修正、**34回すべてを再生成**、さらに**毎日の自動やり直し**と**Whisper検品の本番接続**まで完了した。

**一行で**: 真因は台本でも辞書でもなく、**前回(8/4)に入れた対策層そのもの**だった。
①緑さんシートの語を素の`replace`で当てていた（`は→わ`が文中の全ての「は」を破壊）
②数字を全部かなに開いていた（長いかな列でVOICEPEAKが拗音を落とす）。
**どちらも「誤読を直すために足したもの」が誤読を作っていた。**

## 1. 真因①：緑さんシートを素のreplaceで当てていた

`mac_audio_pipeline.load_reading_overrides()` がシートの語をそのまま `text.replace()` していた。
シートに緑さんが書いた `は → わ`（「死亡数は」が"すうha"と読まれた件の対策）が、**文中の全ての「は」**に当たっていた。

| 台本 | 実際に読まれていた |
|---|---|
| 8年、8件 | **わち**ねん、**わっ**けん |
| はじめに | **わ**じめに |
| 半月板損傷 | **わ**んげつばんそんしょう |
| 政府はがん検診 | せいふ**わ**、がん… |
| 有料老人ホーム | **ゆうしせたい**料老人ホーム（`有→ゆうしせたい`が原因） |

**緑さんメモの「8がわちと誤読」は、シートの2行上の指摘が引き起こした自爆の記録だった。**

### 対策：`vet_overrides()` を新設（`mac_audio_pipeline.py`）
1文字語・数字を含む語・コード側で対応済みの語を**理由付きで弾き**、弾いた件数と理由を必ずログに出す。
24語 → 安全な3語のみ採用。**黙って通さないことが要件**（弾いた語が見えないと同じ事故が再発する）。

難読語は今後 `yomi_preprocess.HARDWORDS` に**コード側で**持つ。シートは補助に降格した。

## 2. 真因②：数字を全部かなに開いていた

8/4に入れた「残った整数はすべて読みに展開する」が誤読の発生源だった。

- 実台本24文のA/B（VOICEPEAK合成→Whisper書き起こし→数値照合）
  **生の数字のまま 53/56一致 ／ 全部かなに展開 38/56一致**
- 崩れ方は拗音の脱落。`にひゃくごじゅうなな`→"に**比約**57"、`きゅうてんきゅうにち`→"**起遊転休日**"、
  `ろっぴゃくじゅうなな`(617)→"6**比約**17"、`じゅうにん`(10人)→"**自由人**"
- **緑さんメモの「10→じゆう」「100→ひやく」はまさにこれ**。かな層が作っていた。

### 決め手：音声長で直接測る
Whisperは「ようか/はちにち」を区別できない（どちらも`8日`と書く）ので判定に使えない。
**生の数字・正しいかな・誤ったかな の3通りを合成して秒数を比べる**と分離できる。

```
8月8日  生=1.72s  はちがつようか=1.71s  はちがつはちにち=1.88s → 正しい
20日    生=1.22s  はつか=1.28s          にじゅうにち=1.43s    → 正しい
40歳    生=1.47s  よんじゅっさい=1.48s   よんじゅうさい=1.49s  → 正しい
1人     生=1.17s  ひとり=1.22s          いちにん=1.26s       → 正しい
```

**＝VOICEPEAKは助数詞の不規則読みを自前で正しく持っている。かな層は利点ゼロで崩れだけ持ち込んでいた。**

### 対策：`to_yomi` から数字変換を全廃
日付・年・助数詞・比率・分数・兆億万・小数・残整数、**すべて数字のまま渡す**。
残したのは「表記自体が読み上げられない」統計表記だけ:

| 表記 | 変換後 | 理由 |
|---|---|---|
| `671千人` `3580.5千人` | `671000人` `3580500人` | 統計表の千人単位 |
| `29201百万円` | `292億100万円` | 統計表の百万円単位（`group_units()`） |
| `93.2％` | `93.2パーセント` | 記号 |
| `10〜15歳` | `10から15歳` | 記号 |

`1千人あたり`（率の分母）は変換しない。桁数条件で除外済み。

あわせて **`mac_audio_pipeline.READING_FIXES` の `([0-9]+)人→\1にん` を削除**。
数字を開かなくなった今は「1人」が「いちにん」になる（VOICEPEAKは「ひとり」と読む）。

## 3. 真因③：台本側で助詞「の」が化けていた

Gemini生成台本にこれが混ざっていた。**カタカナ化（オブ/アンド）は誤答**、日本語に戻すのが正解。

```
各都道府県 of 出生数   → 各都道府県の出生数
モデル世帯의定義       → モデル世帯の定義
And、一般の低所得世帯  → また、一般の低所得世帯
```

`restore_particles()` で日本語に挟まれた `of` / `의` は「の」、行頭の `And、` は「また、」に戻す。
他の文字体系（ハングル等）は `strip_foreign()` で除去。

## 4. 音声が黙って欠ける穴を塞いだ

`synth()` が**終了コードを見ず、ファイルサイズだけで成功判定**していた。
VOICEPEAKは連続実行で時々SIGSEGV（rc=-11）やタイムアウトを起こす。
タイムアウトで殺された前の試行が残した**書きかけwav**を、次の試行が失敗しても「成功」と読み、
本文が途中で切れたまま連結され得た。

対策：毎試行前に出力wavを削除／`rc==0`必須／**実測0.20秒/字に対し0.08秒/字を下回ったら再合成**。

## 5. 唯一残った実誤読：「5月31日」

VOICEPEAKが「ごがつさんじゅう**しち**にち」と読む（37日に聞こえる）。総当たりで実測した結果:

| 表記 | 結果 |
|---|---|
| `3月31日` `12月31日`（数字のまま） | ✓ 正しい |
| `5月31日`（数字のまま） | ✗ 37日 |
| `ごがつさんじゅういちにち`（全部かな） | ✓ 正しい |
| `じゅうにがつさんじゅういちにち` | ✗「自由2月」に崩れる |
| 日だけかな（`5月さんじゅういちにち`） | ✗ 月が「さつき」になる |

**過剰に一般化せず `5月31日` のみ置換**。他の月で誤読が出たら同じ形で足すこと。

## 6. 🔴 拗音はひらがなだと落ちるがカタカナなら残る

`居宅` を直す過程で判明。**HARDWORDSの読みは、拗音(ゃゅょ)を含むならカタカナで書く。**

| 表記 | 聞こえ |
|---|---|
| 居宅（漢字） | 許諾 ＝ きょ**だ**く ✗ |
| きょたく（ひらがな） | 機予託 ＝ き**よ**たく ✗ |
| **キョタク（カタカナ）** | 許託 ＝ きょたく ✓ |

拗音を含まない語はひらがなで問題ない（`くりうらくせんえん` ✓ `あまみわこうえん` ✓）。
ただし**漢字のままだと誤読する**（`奄美和光園`→「天宮公園」、`栗生楽泉園`→「クリオ楽千円」）。

## 7. Whisper検品を本番接続した

翔太さんの指摘で `whisper_qc.py`（従来未接続）を `qc_episode()` として繋いだ。
Geminiにmp3を聴かせる旧`qc_audio`は、mlx_whisper不在時のフォールバックとして残してある。

**指摘を3つに分けたのが肝**:

1. **「前処理で表記変換」** … 意図した直し（`1012.2千人`→`101万2200人`）。
   数値照合を台本でなく**実際に読み上げたテキスト**と突き合わせることで、毎回"欠落"に出ていたのを分離。
2. **「聞き取れなかった数値」** … **要確認であって誤読ではない**。
   今日の実測では、指摘された数値を単文で合成し直すと全て正しく読めていた
   （`100668施設`→10万668 ✓、`5555施設` ✓、`41169組`→4万1169 ✓）。**Whisperの書き起こし癖**。
   ここを誤読として辞書に流すと雑エントリの温床になるので**流さない**。
3. **「指摘」** … 語レベルの誤読だけ承認待ち（`output/dict_pending.json`）へ。辞書は自動更新しない。

書き起こしは `output/qc_transcripts/` に保存＝あとから単文で再検証できる。

### 接続した瞬間に3つの実欠陥が出た（＝繋ぐ価値があった）

1. **Geminiの突合が404で死んでいた**。`whisper_qc`の既定が引退済み`gemini-2.0-flash`で、
   例外時に`ok=True`を返すため**検品が黙って空振り**していた。本体は`gemini-flash-latest`。
   既定を揃え、失敗時は必ずprintするようにした。**世代名の直書きは引退時にこうなる。**
2. `29201百万円` が字面のまま読まれていた（→ 2節の`group_units()`）
3. 難読語4語 `心疾患`(こころしっかん) / `居宅`(きょだく) / `年計`(としけい) / `栗生楽泉園`

## 8. 毎日の自動やり直しを作った

`src/daily_rework.py` ＋ LaunchAgent `com.crosshealth.daily-rework`（**毎日04:00**）。

```
緑さん: Driveで mp3 を「◯回目視聴済_修正点あり」へ移動
   ↓ 毎日04:00
一覧取得 → Notion照合 → Status(Podcast)を「音声化待ち」へ
   ↓
合成は既存の毎時:15のパイプラインが担当（本体は数十秒で終わりロックを長く握らない）
   ↓
処理済みmp3は各フォルダの _修正済_旧 へ退避（+ output/rework_done.json 台帳で二重処理防止）
```

- 監視対象は `*修正点あり` にマッチする**全フォルダ**。3回目・4回目を作っても自動で対象になる。
- 同じ回が別日付で重複していても1本にまとめる（今日の45ファイル→34回）。

### 🔴 ここに最大の罠がある
**launchd配下からはCloudStorage(Google Drive)を一覧できず、しかも`glob`は例外を投げず0件を返す。**
素直に組むと毎日「対象なし」と言い続け、**ログ上は正常に見える**。
だから走査前に `assert_drive_readable()` で確かめ、読めなければ「対象なし」ではなく**失敗としてメール通知**する。

`/usr/bin/python3` に**フルディスクアクセスを付与済み**（翔太さんが2026-08-21に実施）。
launchd上で実測確認済み:
```
トップ一覧: 39件 OK
1回目視聴済_修正点あり/_修正済_旧: mp3 33件
2回目視聴済_修正点あり/_修正済_旧: mp3 12件
```
**空フォルダで「0本」を見ても検証にならない。中身のあるフォルダで確かめること。**
